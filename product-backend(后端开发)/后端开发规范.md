# Bloom Finance 后端开发规范

> 本规范基于 Spring Boot 3.x + Java 17 标准工程，涵盖命名、分层、RESTful、异常、日志、数据库、缓存、安全八大维度。

---

## 1. 项目结构

```
com.bloomfinance
├── common                    # 通用层
│   ├── annotation            # 自定义注解
│   ├── config                # 配置类
│   ├── constant              # 常量定义
│   ├── context               # 上下文 Holder
│   ├── enums                 # 枚举类
│   ├── exception             # 异常定义
│   ├── result                # 统一响应封装
│   └── util                  # 工具类
├── controller                # 控制层
├── service                   # 服务层（接口）
│   └── impl                  # 服务实现
├── repository                # 数据访问层（MyBatis-Plus / JPA）
├── domain                     # 实体层
│   ├── entity                # 数据库实体
│   ├── dto                   # 数据传输对象
│   ├── vo                    # 视图对象
│   └── query                 # 查询条件对象
└── engine                    # 业务引擎（可选）
```

### 层级职责

| 包名 | 职责 | 约束 |
|------|------|------|
| `controller` | 接收 HTTP 请求，参数校验，调用 service | 禁止在此层写业务逻辑 |
| `service` | 核心业务逻辑、事务边界 | 对外暴露接口，impl 以 `ServiceImpl` 结尾 |
| `repository` | 数据持久化操作 | 仅做数据增删改查，不写业务逻辑 |
| `domain/entity` | 数据库表映射 | 与表结构一一对应，禁含业务字段 |
| `domain/dto` | 接收前端参数、跨层传输 | 禁止包含业务方法 |
| `domain/vo` | 返回给前端的聚合数据 | 禁止用于接收参数 |
| `common/exception` | 业务异常定义 | 继承 BusinessException，禁止直接抛 RuntimeException |

### 2.1 类命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 实体类 | `Entity` 结尾 | `UserEntity`、`AccountEntity` |
| DTO | `DTO` 结尾 | `CreateAccountDTO`、`LoginDTO` |

| 仓库接口 | `Repository` 结尾 | `UserRepository`、`AssetRepository` |

### 2.2 方法命名

| 操作 | 命名风格 | 示例 |
|------|----------|------|
| 新增 | `create` | `createUser`、`createAccount` |

| 查询列表 | `list` | `listTransactions`、`listGoals` |
| 分页查询 | `page` | `pageUsers` |
| 统计 | `count` | `countPendingBills` |
| 业务校验 | `check` | `checkUserExists` |

### 2.3 常量与变量

```
类常量：UPPER_SNAKE_CASE    MAX_RETRY_COUNT = 3
局部变量：lowerCamelCase    accountId、monthlyIncome
方法参数：lowerCamelCase    userId、startDate
布尔变量：is/has/can 前缀   isActive、hasPermission
```

### 2.4 数据库表与字段

```
表名：snake_case，单数名词    t_user、t_account、t_transaction
字段名：snake_case          user_id、created_at、asset_type
主键：id                     自增主键
外键：xxx_id                 user_id、account_id
时间戳：created_at / updated_at
```

## 3. RESTful 规范

### 3.1 URL 设计

```
GET    /api/v1/users              # 查询用户列表
GET    /api/v1/users/{id}         # 查询单个用户
POST   /api/v1/users               # 创建用户
PUT    /api/v1/users/{id}          # 更新用户
DELETE /api/v1/users/{id}          # 删除用户
PATCH  /api/v1/users/{id}/status   # 部分更新（如状态）
```

### 3.2 请求与响应规范

**统一响应格式：**
```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "timestamp": 1716200000000,
  "traceId": "abc123"
}
```

**分页响应格式：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [...],
    "total": 100,
    "size": 20,
    "current": 1,
    "pages": 5
  }
}
```

### 3.3 状态码规范

| 状态码 | 含义 | 使用场景 |
|--------|------|----------|
| 200 | OK | 成功 |
| 201 | Created | 资源创建成功 |
| 204 | No Content | 删除成功 |
| 400 | Bad Request | 参数校验失败 |
| 401 | Unauthorized | 未登录 |
| 403 | Forbidden | 无权限 |
| 404 | Not Found | 资源不存在 |
| 409 | Conflict | 数据冲突（如重复） |
| 422 | Unprocessable Entity | 业务校验失败 |
| 500 | Internal Server Error | 服务器异常 |

## 4. 控制器开发规范

### 4.1 标准控制器模板

```java
@RestController
@RequestMapping("/api/v1/accounts")
@RequiredArgsConstructor
@Slf4j
public class AccountController {

    private final AccountService accountService;

    @GetMapping("/{id}")
    public Result<AccountVO> getById(@PathVariable Long id) {
        return Result.success(accountService.getAccountById(id));
    }

    @PostMapping
    public Result<Long> create(@Validated @RequestBody CreateAccountDTO dto) {
        return Result.created(accountService.createAccount(dto));
    }

    @GetMapping
    public Result<PageResult<AccountVO>> page(AccountQuery query) {
        return Result.success(accountService.pageAccounts(query));
    }
}
```

### 4.2 参数校验

```java
// 必填字段使用 @NotNull / @NotBlank / @NotEmpty
// 字符串长度使用 @Size
// 数值范围使用 @Min / @Max
// 邮箱、手机号使用正则或自定义注解
@PostMapping
public Result<Void> create(@Validated @RequestBody CreateAccountDTO dto) {
    // 分组校验：@Validated(CreateGroup.class)
}
```

### 4.3 禁止在 Controller 中

- 直接操作数据库
- 编写业务逻辑
- 捕获业务异常后自行处理（统一异常处理器负责）

## 5. 服务层开发规范

### 5.1 标准服务模板

```java
@Service
@RequiredArgsConstructor
@Slf4j
@Transactional(rollbackFor = Exception.class)
public class AccountServiceImpl implements AccountService {

    private final AccountRepository accountRepository;
    private final AssetCalculator assetCalculator;

    @Override
    public AccountVO getAccountById(Long id) {
        AccountEntity entity = accountRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("账户不存在"));
        return ConverterUtil.toVO(entity);
    }

    @Override
    @Transactional(propagation = Propagation.NOT_SUPPORTED)
    public PageResult<AccountVO> pageAccounts(AccountQuery query) {
        // 只读事务，不加锁
        IPage<AccountEntity> page = accountRepository.page(query);
        return PageResult.of(page, AccountVO.class);
    }

    @Override
    public Long createAccount(CreateAccountDTO dto) {
        // 业务校验
        checkDuplicateAccount(dto);
        // 转换并保存
        AccountEntity entity = ConverterUtil.toEntity(dto, AccountEntity.class);
        return accountRepository.save(entity).getId();
    }
}
```

### 5.2 事务规范

| 场景 | 事务属性 | 说明 |
|------|----------|------|
| 增删改操作 | `required`（默认） | 开启新事务或加入当前事务 |
| 纯查询方法 | `NOT_SUPPORTED` | 挂起事务，避免不必要锁 |
| 多数据源写入 | `REQUIRES_NEW` | 新开事务独立提交 |
| 嵌套服务调用 | 根据业务判断 | 避免事务传播导致长事务 |

## 6. 异常处理规范

### 6.1 自定义异常体系

```java
// 基础异常
public class BusinessException extends RuntimeException {
    private final int code;
    private final String message;
}

// 特定异常
public class ResourceNotFoundException extends BusinessException {
    public ResourceNotFoundException(String message) {
        super(404, message);
    }
}

public class ValidationException extends BusinessException {
    public ValidationException(String message) {
        super(422, message);
    }
}

public class UnauthorizedException extends BusinessException {
    public UnauthorizedException(String message) {
        super(401, message);
    }
}
```

### 6.2 全局异常处理器

```java
@RestControllerAdvice
@RequiredArgsConstructor
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusiness(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidation(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining("; "));
        return Result.fail(400, message);
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleSystem(Exception e) {
        log.error("系统异常", e);
        return Result.fail(500, "系统异常，请稍后重试");
    }
}
```

## 7. 日志规范

### 7.1 日志级别使用

| 级别 | 使用场景 |
|------|----------|
| `ERROR` | 异常、失败操作、需要人工介入 |
| `WARN` | 业务校验失败、接近阈值、风控拦截 |
| `INFO` | 关键业务流程节点（登录、支付、创建） |
| `DEBUG` | 开发调试、SQL 输出（生产环境关闭） |

### 7.2 日志规范

```java
// 使用占位符，禁止字符串拼接
log.info("用户登录成功, userId={}, ip={}", userId, ip);

// 敏感信息脱敏
log.info("创建订单, orderNo={}, amount={}", orderNo, maskAmount(amount));

// 禁止记录
// - 用户密码、支付密码
// - 完整身份证号、银行卡号
// - Token 明文（可记录脱敏后前几位）
```

## 8. 数据库规范

### 8.1 建表规范

```sql
CREATE TABLE t_account (
    id           BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
    user_id      BIGINT UNSIGNED NOT NULL COMMENT '用户ID',
    account_type TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '账户类型: 1-储蓄卡 2-信用卡 ...',
    bank_name    VARCHAR(64) NOT NULL COMMENT '银行名称',
    card_no      VARCHAR(32) NOT NULL COMMENT '卡号(加密存储)',
    balance      DECIMAL(18,2) NOT NULL DEFAULT 0.00 COMMENT '余额',
    status       TINYINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '状态: 0-冻结 1-正常',
    created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted      TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0-未删除 1-已删除',
    INDEX idx_user_id (user_id),
    INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账户表';
```

### 8.2 索引规范

- 单表索引数量不超过 5 个
- 联合索引控制在 3 列以内
- 区分度低的字段（status、deleted）不建索引
- 禁止在外键上建索引（逻辑外键由应用层控制）

### 8.3 SQL 规范

```xml
<!-- MyBatis-Plus QueryWrapper 使用示例 -->
<select id="pageAccounts" resultType="AccountEntity">
    SELECT * FROM t_account
    WHERE deleted = 0
    <if test="userId != null">
        AND user_id = #{userId}
    </if>
    <if test="accountType != null">
        AND account_type = #{accountType}
    </if>
    ORDER BY created_at DESC
</select>
```

## 9. Redis 缓存规范

### 9.1 缓存Key命名

```
格式：{module}:{entity}:{identifier}:{field}

示例：
bloom:user:123:profile          # 用户基础信息
bloom:account:456:balance        # 账户余额
bloom:auth:token:abc123          # 登录Token
bloom:goal:789:progress          # 目标进度
```

### 9.2 缓存策略

| 数据类型 | TTL | 说明 |
|----------|-----|------|
| 用户信息 | 30min | 可视业务调整 |
| 账户余额 | 5min | 实时性要求高 |
| 目标进度 | 10min | 相对稳定 |
| Token | 7day | 与登录态同步 |
| 验证码 | 5min | 用完即删 |

### 9.3 缓存注解使用

```java
// 读穿缓存
@Cacheable(value = "user:profile", key = "#userId", unless = "#result == null")
public UserProfileVO getUserProfile(Long userId) { ... }

// 写更新缓存
@CachePut(value = "user:profile", key = "#userId")
public UserProfileVO updateProfile(Long userId, UpdateProfileDTO dto) { ... }

// 删清除缓存
@CacheEvict(value = "user:profile", key = "#userId")
public void deleteUser(Long userId) { ... }

// 批量清除
@CacheEvict(value = "user:*", allEntries = true)
public void clearUserCache() { ... }
```

## 10. API 安全规范

### 10.1 认证鉴权

- 所有业务接口须通过 `Authorization: Bearer <token>` 认证
- Token 有效期：AccessToken 2小时，RefreshToken 7天
- 敏感操作（转账、修改密码）：需二次验证或短信确认

### 10.2 参数安全

```java
// 金额类参数使用 BigDecimal，禁止用 double
private BigDecimal amount;

// 防止 SQL 注入：禁止拼接 SQL，全部使用参数化查询
// 防止 XSS：前端过滤，后端双重验证
// 防止 CSRF：Token 校验（同源策略 + CSRF Token）
```

### 10.3 敏感数据

- 数据库密码、API 密钥存于 `application-{profile}.yml`，禁止提交 Git
- 银行卡号、身份证号加密存储（AES-256）
- 日志中禁止明文记录敏感信息

## 12. Git 提交规范

### 12.1 Commit Message 格式

```
<type>(<scope>): <subject>

feat(account): 新增账户绑定功能
fix(auth): 修复登录Token过期后未正确返回401的问题
chore(deps): 升级Spring Boot至3.2.0
docs(readme): 更新接口文档
style(code): 格式化代码（无逻辑变更）
refactor(asset): 重构资产计算逻辑
test(asset): 新增资产统计单元测试
perf(account): 优化账户查询性能
```

### 12.2 Type 说明

| Type | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug 修复 |
| docs | 文档更新 |
| style | 代码格式（不影响功能） |
| refactor | 重构（非新功能非修复） |
| test | 测试相关 |
| chore | 构建/工具链变更 |
| perf | 性能优化 |

### 12.3 分支命名

```
main                    # 主分支（生产环境）
develop                 # 开发分支
feature/account-binding # 功能分支
fix/login-redirect      # 修复分支
release/v1.0.0          # 发布分支
hotfix/critical-bug     # 紧急修复分支
```
